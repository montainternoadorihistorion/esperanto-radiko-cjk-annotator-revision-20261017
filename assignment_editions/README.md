# 漢字割り当ての二つの版

利用者が選ぶ版は、順変換・逆変換とも次の二つだけです。

- `legacy`（旧版・固定）：今回の一連の割り当て見直し前、正本 commit `4c16c8937c601fdc149ccb8cbba1b6085cc94692` の割り当て。旧正本の SHA-256 は `8ee9e27651413f87f1404eb5c328e7ad8ba4bda3be61a442ac9585911a4a9600`。旧データに残っていた明確な `@` 用旧値 10 語根は、この旧正本へ合わせています。
- `current`（新版・更新中）：現在の承認済み割り当て。今後の修正も、この同じ選択肢へ反映します。修正のたびに中間版の選択肢を追加しません。

旧版の圧縮データ、CSV、正本の出所、修正箇所と全件検証は `legacy/manifest.json` に記録します。旧版の固定資産を通常の割り当て更新で変更してはいけません。

変換エンジンと学習用注釈は両版で共通の現行版を使います。このため、旧版は過去の画面出力をそのまま再現するものではありません。`@` の消去、保護区間などのエンジン修正は共有します。一方、旧漢字データに組み込まれた語根分解は固定しており、後発のデータに依存する分解改善まで新版と同じとは扱いません。

手動補正は分解形を保持し、漢字表示を選択した版の CSV から描き直します。保存された漢字 HTML を、別の版へそのまま持ち越しません。注釈は共通の現行 CSV で描画します。

画面・手動補正・ダウンロードは `current` / `legacy` を共通に参照します。結果には生成時の版、データと処理コードの内容ハッシュ、使用した補正、モード・文字表記、作成時刻を記録します。辞書更新の識別に、手動更新の版番号だけを使いません。版・辞書・補正・モードが変わった結果は再変換を促します。HTML ダウンロードにはメタ情報を付し、ファイル名にも版と結果ハッシュを入れます。

自作 JSON はこの二つの割り当てを自動適用する対象ではありません。アップロード内容の SHA-256 と `source_id=custom_json` を保存します。既存の自動語根補正には共通の最新注釈を使用することを画面に明示します。

大きな置換 JSON は選択した版・モードだけを読み、メイン画面と手動補正画面で同じ 1 エントリーのキャッシュを共有します。旧版は gzip のまま配布します。大データのダウンロード URL は、実際の公開リポジトリのチェックアウト commit とファイル内容が一致するときだけ、その commit に固定して作ります。未コミット内容や統合私有コピーから、異なるデータへのリンクを発行しません。

逆変換の過去の内部 API 識別子は、既存連携を壊さないための互換情報です。画面に中間版を増やす根拠にはしません。旧版に元からある分解差・逆変換の曖昧さは、今回の新規退行と区別して記録します。
