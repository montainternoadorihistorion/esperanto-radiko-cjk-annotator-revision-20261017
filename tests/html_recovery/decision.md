# 標準HTMLの原語復元モード

2026-10-18、ユーザー承認に基づく追加。日中の逆変換アプリへ独立モードを設ける。既存の平文逆変換、新旧の漢字割り当て、識別子、語根分解は変更しない。

## 復元方法

- 対象は日中韓の順変換アプリが出す幅調整付きの完全な標準HTML。
- 漢字ルビでは `rt`、注釈ルビでは `ruby` の本文を原語として読む。形式は明示選択し、文字種から推測しない。
- `p.text-M_M` の本文だけを読み、head・title・CSSを本文へ混入させない。
- HTML内の原語を読み取るので、通常の逆変換辞書を後から適用しない。保護された漢字、文字として残る `@`、大文字は保持する。
- 本文の `<br>\n` は一つの改行に戻し、`rt` 内のレイアウト用 `<br>` は連結する。段落開始直後の生成器由来の改行だけを除き、前後の空白や空行を削らない。
- 文字参照は一度だけ読み、読み戻した `<ruby>` などをHTMLとして再解釈しない。
- UTF-8（BOM可）のアップロードとソース貼り付けに対応する。10 MiBを超える入力、欠損構造、未知タグ・不正な閉じ方はエラーにする。入力HTMLを実行・表示しない。
- 入力・入力方法・ルビ形式・モードの変更で以前のHTML結果を消去し、内容のハッシュでも照合する。ダウンロードは結果と同じUTF-8本文を使用する。

## 意図と限界

`dekdu` の表示上のハイフン、`etilo` の漢字の逆引き先、`revidi` と `adiaŭi` の表記共用は、HTMLに保持された原語から復元できる。これらを理由に割り当てや識別子を変更しない。

復元はHTMLに残る表記に限る。順変換で統一された字上符表記・特殊空白・改行コードや、使用済みの `@` / `%` 指定記号は復元できない。既存HTMLにルビ方向の記録はなく、選択間違い・編集・方向の混在を完全には検出できない。版コメントは来歴情報であり真正性の証明ではない。汎用Webページ、断片HTML、画像や追加タグを使った編集HTMLは対象外。

## 検証の区分

各アプリの `tests/test_html_source_recovery.py` は実出力12経路と境界条件を検証し、`tests/test_html_recovery_ui.py` は入力切替・古い結果の除去・実ダウンロード引数・辞書処理の非到達を検証する。`local_validation.json` は残存不一致として保存した11,677表面形（語根数ではない）と実出力の独立検証記録。保存済みCloudファイルの再読取と、配備後に行うCloud実画面の検証は分けて記録する。
