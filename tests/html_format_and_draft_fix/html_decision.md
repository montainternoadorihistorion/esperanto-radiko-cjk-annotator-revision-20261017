# 標準HTMLの形式取り違え防止

漢字ルビと注釈ルビではエスペラントが残る側が逆なので、復元時の形式を間違えると、構造上は正しいHTMLから漢字や訳を取り出してしまう。新版の漢字ルビ `lasis` を注釈として読むと `放is`、旧版なら `留is` になる。形式を推測せず、生成時に確定できる範囲だけ記録して明示選択と照合する。

## 生成と保存

日中韓の同梱の標準2モードを使い、保存対象が生成直後のHTMLと完全一致する場合だけ、保存用のコピーのheadへ `esperanto-ruby-mode` を追加する。値は `kanji` または `annotation`。既存の版・署名・日時の先頭コメントは変えない。

生成結果・編集欄には追加しない。編集済みHTML、自作JSON、純粋置換、標準以外の形式には自動付記しない。編集欄でルビの向きを変更しても、元モードの情報で復元方向を固定しない。ソース欄からのコピーは、従来どおり形式情報なしで明示選択を使う。

## 復元

日中の復元器で、専用metaの有効な値が利用者の明示選択と一致するときは従来と同じ側を取り出す。記録と不一致、空・未知値、重複・矛盾には理由を示し、復元結果と保存ボタンを出さない。入力・保持中のファイル・平文用の選択版は残す。方向を無言で変更しない。

形式情報のない既存HTMLには従来の明示選択を使う。一般のmetaの受理やHTML構造検査は変更しない。`custom_json` と記録された文書では専用metaも従来の一般metaとして扱い、形式照合や新たな値検証を適用しない。自作JSONの形式名は任意の置換HTMLの向きを証明しないためである。

形式情報は生成時の来歴であり、外部編集・混在した本文の正しさを保証しない。漢字割り当て・識別子・語根分解・通常/@変換・平文逆変換・入力保持の仕組みは変更しない。

## 局所検証

- 日中の新しい復元テストは各33件成功。新旧・3言語の既存HTML、空白・改行・保護文字、正しい方向、誤方向、専用metaの不正値、一般meta、自作JSON、入力/版/ファイル保持、古い結果の保存防止を含む。
- 日中韓の実際の生成画面をAppTestで別プロセス実行。未編集保存12件、ルビ方向を書き換えた編集済み保存12件、自作JSON保存3件の計27件を検証。保存内容と編集欄を区別し、日中の両復元器で確認した。アップロード・ダウンロードの転送部分を計測用に置き換え、生成・編集・保存確認の実処理を使った。
- 全体回帰・Cloud確認は別の統合検証記録に記載する。この局所検証を全語彙検査やCloud操作とは扱わない。
