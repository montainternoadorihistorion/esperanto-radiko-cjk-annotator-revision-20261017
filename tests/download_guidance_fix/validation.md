# 配布JSON・手動補正バックアップの案内改善

2026-10-19。実装は PR #60、Cloud確認時のソースは `a9427afff3e1f3e591a36db04bf759d8b6cfcf3e`。

## 画面で明示したこと

- 配布JSONは置換表の原本であり、アプリ実行時の自動補正や同梱データ専用処理のすべてを含まない。
- 同じ結果には、対応するソース・データ、言語、原文、新旧の選択、変換モード、文字表記などをそろえる。手動補正を使った場合は、現在有効な補正のバックアップも保存する。
- データページの `user_corrections.json` は同梱原本。手動補正ページのバックアップは、セッションでの追加・読み込み・削除を反映した現在有効な補正。
- 旧版は割り当てが固定される一方、処理上の修正は適用される。自作JSONの従来の適用範囲も説明する。
- 実ファイルとの一致を確認できた固定ソース版への閲覧・ZIPリンクと、手動補正ページとの相互リンクを追加した。

今回は説明・導線だけの変更であり、漢字割り当て、識別子、語根分解、通常／@変換、平文逆変換、HTML復元、自作JSONの処理は変更していない。前回の約2,590万回の全件検査を再実行したという意味ではなく、データ・処理の不変性と既存CI・今回の画面／保存検証で確認した。

Chromeでは通常URLの外枠が読み込み中になる既知の自動操作時の現象があったため、同じページのDOMに表示されたアプリ内部URLへ移動して確認した。通常URLの外枠を今回修正・検証したという意味ではない。

版切替直後の最初の記録では、上部の版表示だけが更新され、下部の旧画面が残る再描画途中を捕捉していた。記録を消さずに保存し、画面更新の完了後に6状態を再取得した。最終照合は `cloud/page_records.json` の行番号ではなく配列インデックス6–11の最新記録を使う。ダウンロード済み42ファイルはすべて正しい版で一致していた。

根拠: `review/cloud_evidence_review.json`、`review/summary.json`、`audit/audit_runtime_proof.json`、`audit/audit_bundled_raw_boundary.json`、`audit/ci_summary.json`。Cloudのネイティブ保存と、固定リンクのHTTP取得・ZIP照合は別の検証として記録する。

大容量データのHTTP取得では、1件でContent-Lengthより短い応答を確認したため、範囲を分けて取得して最終ファイルの長さ・SHA-256を照合した。別の1件は再取得で完全一致したが、最初の応答の詳細を保存できておらず原因は断定していない。どちらも完成した取得内容の不一致やアプリのデータ変更は確認されていない。

ZIPはHTTPで直接取得して内容を検証した。ブラウザからのZIP保存も試みたが、操作待ちが終了せず保存先を確認できなかったため、ブラウザで検証済みの42ファイルには含めていない。ZIPの一時コピーは検証後に削除済み。
