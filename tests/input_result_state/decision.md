# 原文・選択版と保存結果の対応

2026-10-18、ユーザー承認に基づくUI修正。漢字割り当て、識別子、語根分解、順逆変換の辞書と算法は変更しない。旧版の3試験形は別途検討する。

## 修正する動作

- 順変換は現在の原文と結果を対応付ける。原文・入力ファイル・版・形式が変わった場合は再変換するまで古い結果を保存できないようにする。
- 結果の保存は「保存内容を確認」から、確定した内容の確認画面を開いて行う。編集画面へ直接ダウンロードボタンを置かず、確認画面に渡した同じ内容を表示・保存する。閉じた後は再確認する。
- 原文の変更を認識できる入力欄とするが、変換自体は明示的なボタン操作でのみ実行する。
- 平文逆変換の結果欄を読み取り専用にし、画面表示とダウンロードを一致させる。
- 平文とHTML復元を往復しても原文・選択版を保持する。HTMLの貼付け原稿、形式と入力方法も保持する。以前の結果を無効にする防御は維持する。
- 標準HTMLのアップロードは検証済みの原文とファイル名を保持する。ファイルを外したり不正なファイルへ変更した場合は、以前の入力・結果へ戻らない。
- 順変換のテキストアップロードはUTF-8を厳密に確認し、空ファイルを未アップロードと区別する。純粋置換の保存形式はtext/plainに合わせる。

## 検証

UI操作の前後で原文・選択版・表示結果・実ダウンロードを照合する。新旧、通常/@、純粋置換・漢字/注釈ルビ、平文逆変換・HTML復元を含める。既存データと処理本体の不変性、保存済み網羅検査の再読取、今回の実処理試験を区別して記録する。ローカル検証後にCloud上でも確認する。

## 編集直後のダウンロード

原文の一致をサーバ側で確認するだけでは、編集直後のダウンロードが画面更新より先に走る場合がある。実ブラウザで `lasis` の変換後に原文を `ananaso` へ変更し、直ちに保存すると旧結果の `放is` がダウンロードされることを再現した。

この挙動は[Streamlitのダウンロード仕様・Example 2](https://docs.streamlit.io/develop/api-reference/widgets/st.download_button)でも説明されている。今回は通常ボタンで最新入力を照合してから、読み取り専用の確認画面に確定した結果だけを渡す。実ダウンロードはその画面内で `on_click="ignore"` を使用し、確認中の内容をそのまま保存する。変換処理や辞書の変更で対処しない。
